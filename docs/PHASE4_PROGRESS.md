# 第四阶段进展：跨文档评测与论文比较

更新日期：2026-11-13。

## 本阶段完成

- 扩展官方材料回归集，涵盖 Transformer v7、CLIP 和《Understanding Deep Learning》三份材料，共 14 道问题：6 道 CLIP、6 道教材、2 道跨论文比较题。
- 为问题标注预期证据页和人工事实要点，新增可复跑脚本：

  ```bash
  cd backend
  TRACESCHOLAR_SAMPLE_DIR="/path/to/科研小助手/pdf" ./.venv/bin/python scripts/evaluate_official_corpus.py
  ```

- 新增 `POST /api/research/compare`：支持明确选择 2–5 篇论文，按篇独立检索并交错组织证据，降低单篇论文挤占其他来源的风险。
- 比较前要求每一篇所选论文都至少有一条正文和页码有效的证据；任何来源缺失时停止生成，保留已找到的片段供用户检查。
- 比较答案需引用每一篇所选论文中的证据；未覆盖任一选定来源时拒绝展示回答。
- 中文工作台新增“多篇比较”模式和论文勾选入口；单篇检索保持原有流程。
- 普通全库检索可以按研究工作轮流取回候选，避免前几条结果全部来自同一篇文献。
- 英文词项归一化补充常见复数、过去式和连字符拆分，帮助跨语句形式的术语匹配。

## 离线评测

在三份官方 PDF 同时入库、无需模型调用的条件下：

| 指标 | 结果 | 解释 |
| --- | ---: | --- |
| 指定论文范围内页码命中@6 | 87.5%（16 次来源检查） | 单篇题使用对应论文范围；比较题逐篇检索 |
| 全库检索页码命中@6 | 66.7%（12 道单篇题） | 同时检索三份材料，未要求用户先选来源 |
| 证据要点覆盖@6 | 85.4%（48 组要点） | 原文片段中出现人工标注的要点字符串 |
| 比较来源覆盖 | 100%（2 道比较题） | 两篇所选论文均有有效引用 |

指定论文范围下的结果高于全库检索，说明选择相关论文能减少长教材与相近术语造成的干扰。该题集规模有限，字符串覆盖只检查证据片段，不代表生成回答的事实正确率。

## 验证与边界

- 官方 PDF 全量回归：`85 passed`；前端 JavaScript 检查、Python 编译和 `git diff --check` 均通过。
- 使用论文正文和 `TestClient` 验证比较接口、缺失证据门禁、每篇引用校验和前端入口；相关自动化测试包含在全量测试中。
- 对真实 DeepSeek 跨论文请求进行了 1 次小样本尝试，但模型服务请求超时，未能取得真实回答。因此本阶段比较回答的端到端逻辑已由模拟模型测试验证，真实模型生成尚待网络可用时复测；这次超时不表示密钥错误。
- 仍未接入稠密语义 embedding 和神经重排。全库检索表现较弱时，可先选择论文范围；后续应扩大问题集并进一步调优全库文档识别，再判断是否需要模型化检索组件。
- OCR、长任务进度和断点恢复、跨版本差异报告及多论文结构化数据抽取仍待开发。
