# 第三阶段进展：评测驱动检索与轻量科研 Agent

更新日期：2026-11-13。

## 当前完成

- 建立 22 道官方 Transformer v7 中英混合检索题，覆盖概念、结构、方法、实验结果、无答案拒答；每道可回答问题标注预期证据页。
- 增加可复跑脚本：

  ```bash
  cd backend
  TRACESCHOLAR_SAMPLE_DIR="/path/to/科研小助手/pdf" ./.venv/bin/python scripts/evaluate_retrieval.py
  ```

  排序器消融可用 `--ranker legacy|bm25|cosine|hybrid` 选择；默认是 BM25。回答评测另用：

  ```bash
  TRACESCHOLAR_SAMPLE_DIR="/path/to/科研小助手/pdf" ./.venv/bin/python scripts/evaluate_answers.py --answerable-limit 6
  ```

  回答评测最多请求 6 次模型，只包含 6 道可回答题；另 2 道资料外题由本地证据门禁拒答，不调用模型。脚本不会打印或保存密钥，也不会输出完整回答。

- 对基线关键词检索运行同一评测，首条页命中率为 65%，前三条页召回率为 65%，前五条为 75%。
- 加入常见英文词形归一化、自然语言说法规范化、已覆盖科研术语的中英桥接，以及章节标题相关性加权后，首条页命中率为 90%，前三条和前五条页召回率均为 100%。两道不可回答问题均未检索到证据，误召回率为 0%。
- 增加 BM25、TF-IDF 稀疏向量余弦相似度和 Reciprocal Rank Fusion 融合排序，可离线用相同评测集对比；生产默认使用 BM25。
- 基于原文人工标注 20 道可回答题的关键证据事实组，新增前三条证据覆盖率检查。
- 新增 `POST /api/research/agent`：识别概念、方法、结果、比较、总结等意图，选择仅检索或证据问答流程；先检查证据正文与页码，再按意图组织回答，最后验证引用。
- 用户明确只要求找原文时，Agent 返回检索证据而不调用模型；没有有效证据时停止流程，不会调用模型补答案。
- 前端“智能体回答”入口展示最终回答、引用，以及可展开查看的执行步骤。
- 按照意图调整回答组织方式：概念先解释、方法按步骤梳理、结果保留指标背景、比较限制在实际检索到的来源内。

## 验证

- 组委会 PDF 全量回归（包含 Agent 与检索评测）：`78 passed`。
- 前端脚本通过 `node --check`；工作区通过 `git diff --check`。
- 对同一篇官方 Transformer v7 PDF、相同 22 题的排序器对比：

  | 排序方式 | 页 Hit@1 | 页 Recall@3 | 人工要点证据覆盖率@3 | 无答案误召回 |
  | --- | ---: | ---: | ---: | ---: |
  | 现有 TF/IDF 词项排序 | 95% | 100% | 94% | 0/2 |
  | 稀疏 TF-IDF 余弦 | 75% | 100% | 94% | 0/2 |
  | BM25 | 100% | 100% | 96% | 0/2 |
  | BM25 + TF/IDF + 余弦排名融合 | 100% | 100% | 96% | 0/2 |

- DeepSeek 小样本回答检查覆盖 6 道概念、方法、注意力计算、多头机制、位置编码和实验结果问题；成功回答均保留有效引用并命中预期页，人工标注核心事实组覆盖率为 100%。两道无答案题均正确拒答。题组很小，且字符串要点匹配不能取代人工判断；运行中有两次模型空回答，经单题重试后成功，所以模型服务暂时性空响应仍需关注。

- 结果仅适用于当前一篇论文与人工编写的 22 题。事实要点覆盖检查测量的是前三条原文证据是否包含标注线索，不是模型生成答案的准确率；尚未使用模型裁判或人工盲评评估最终回答。

## 当前边界与下一步

- 当前 BM25 与 TF-IDF 余弦都是词项级稀疏方法，不具备稠密语义向量能力；当前小样本上余弦单独排序未带来提升，BM25 已达到该测试集满分。没有引入会下载模型权重的依赖，因此没有额外部署体积、内存和费用。
- 意图识别是可解释的规则路由，步骤记录随 API 回包提供，尚无持久化运行日志、计划重试或动态工具调用。
- 回答评测是小规模、人工列事实组的本地脚本检查，没有做人工盲评，也没有独立模型裁判；自然语言语义覆盖的自动匹配可能漏掉有效改述。
- 下一步优先把评测扩展到官方包中的 CLIP 论文和深度学习教材，加入跨文档干扰题，再重新决定是否有必要接入本地 embedding 模型；之后拓展多论文结构化比较和更复杂的 Agent 流程。
