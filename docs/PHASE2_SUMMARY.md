# 第二阶段总结：证据检索与可追溯问答

完成日期：2026-11-13。

## 阶段结论

第二阶段已完成。当前版本实现了从论文文本检索证据、基于证据生成回答、展示引用来源到跳转论文原页的完整问答闭环。这里的“完成”指阶段约定的证据问答能力已经可用，不代表已经实现向量检索、完整 Agent 或大规模效果评测；这些列为后续阶段工作。

## 完成内容

- 提供本地证据检索和证据回答接口：`POST /api/research/retrieve`、`POST /api/research/answer`。
- 使用关键词与 TF/IDF 风格排序检索本地论文文本，可限定论文范围；弱匹配和无相关证据时会返回资料不足。
- 为常见中英混合科研问法补充术语桥接，使部分中文问题可以检索英文论文。该能力覆盖常见词条，不是通用翻译。
- 回答调用 DeepSeek，并要求模型只依据检索证据作答、按提问语言回复、用 `[E1]` 等标签引用来源。
- 引用由本地检索结果生成并校验；无有效证据引用的回答会被拒绝。无检索证据时不会调用模型。
- 证据卡片显示论文、版本、章节和页码；原文片段默认折叠，用户可以展开查看，或跳转到论文对应页面。
- 回答提示词鼓励用自然语言说明数学关系；页面对常见 LaTeX 数学标记做隐藏处理，降低公式源码直接出现在回答中的情况。
- 兼容早期已入库、尚无结构化文本块的论文数据，可从逐页文本即时构建检索块。

## 验收与验证

- 在组委会材料目录上运行完整测试：`70 passed`，覆盖论文版本识别、结构解析、扫描版 OCR 状态、长文档解析以及问答链路。
- 对本地 CLIP 论文完成 DeepSeek 真实接口调用验证：回答带有证据引用，来源页码可对应回原文。该单次验证不等于统计意义上的准确率评测。
- 中文问题检索英文论文、无关问题返回资料不足、证据卡片跳页等场景已有自动化或手工验证。
- 前端 JavaScript 语法检查通过；公式过滤样例验证了行内和块级 LaTeX 不会原样显示。

## 当前边界

- 检索仍以关键词和 TF/IDF 风格排序为主，中文术语桥接范围有限；尚未接入向量检索和重排。
- 自动测试检查接口行为与安全边界，但尚未形成覆盖多种问法的基准集，也没有统计检索召回率、引用准确率和回答正确性。
- 目前是固定的“检索后回答”流程，还没有意图识别、工具选择和多步执行的 Agent。
- 跨版本差异报告和多篇论文结构化比较尚未实现。
- 模型回答仍需核对原文；引用有效只能说明来源存在，不保证模型解释一定正确。公网 Render 部署在代码更新后仍应进行一次实际问答检查。

## 建议的第三阶段方向

建议把第三阶段聚焦为“评测驱动的轻量科研 Agent”，先做一小批官方论文问题和预期证据页码作为基准，再让 Agent 根据问题选择现有检索、证据回答等工具，并展示执行路径与引用。向量检索和重排可以依据基准结果决定是否纳入，避免在没有效果数据时盲目增加组件。具体范围和优先级待讨论确认后再开始。
