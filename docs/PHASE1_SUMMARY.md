# TraceScholar 第一阶段总结：基础系统与公网演示

> 阶段结论：第一阶段的基础系统已完成，并已部署到公网进行演示。当前项目具备论文 PDF 导入、基础解析、版本识别、论文库浏览和基础访问保护；可用于展示“科研论文资料管理与可追溯解析”的起点。RAG 检索、证据问答和 Agent 尚未实现，不应把它们描述为已完成。

## 一、项目目标与方向

TraceScholar（可信科研助手）定位为面向科研文献的通用助手。第一阶段选择论文 PDF 作为重点验证场景，先打好资料导入、解析、版本管理和来源追踪的工程基础，再逐步扩展到可验证的科研问答和多论文分析。

这个方向不是把毕业设计报告审核平台原样搬来：只复用与领域无关、确实有用的工程经验；论文审核规则、原有业务页面及数据库不直接并入本项目。

## 二、第一阶段的推进过程

1. **梳理比赛目标与已有材料。** 对照赛项介绍、往届赛题和今年的参赛资料，先确定作品需要围绕科研 Agent 与论文材料构建，而不是只做静态展示页。
2. **确定可落地的项目主线。** 采用“通用科研助手 Agent，以科研论文资料作为重点验证场景”的思路，优先保证系统能力真实可用，避免仅靠领域标签包装。
3. **盘点可复用代码与比赛样例。** 检查毕设平台和“科研小助手”材料，保留适合的工程思路；用官方论文和教材样例规划可重复验收流程。
4. **建立独立项目并完成首轮界面。** 创建 TraceScholar 项目骨架和中文工作台，加入论文库、资料导入和论文阅读入口；根据反馈调整中文布局。
5. **实现论文导入与基础解析。** 建立后端 API、PDF 校验、分页抽取、题名/作者/摘要和基础结构提取，并记录论文版本、章节、文本块和来源信息。
6. **补齐部署与演示保护。** 加入 Docker 部署配置、生产环境登录保护、上传和存储限制、健康检查及部署说明。
7. **推送代码并完成公网部署。** 代码由 GitHub 仓库提供，使用 Render 免费 Web Service 部署；首次部署成功后，在公网地址登录并导入公开样例进行实际演示。

## 三、已实现的功能

### 用户界面

- 中文科研工作台和论文库页面。
- 导入 PDF 论文，并查看论文列表、作者、页数和解析状态。
- 查看论文详情和逐页提取的文本。
- 提供搜索栏及面向后续问答、对比、研究图谱的界面入口；尚未开放的能力明确标注为即将开放。

### 后端与文献处理

- FastAPI 后端，提供首页、静态资源、健康检查、上传、论文列表与详情、分页内容、结构和文本块等接口。
- PDF 文件类型、大小、页数和加密状态检查；基于 SHA-256 的完全相同文件去重。
- 按页抽取文本，识别题名、作者、摘要，并完成基础章节结构解析。
- 对 arXiv 论文识别论文 ID 与版本关系：不同版本共享同一研究工作标识，不覆盖已保存的版本；可提示上传的版本较旧。
- 为章节、文本块保留论文版本、页码和章节等来源元数据，为后续证据检索打基础。
- 对扫描页面标记“待 OCR”；当前**只有待处理状态，没有 OCR 文字识别能力**。

### 部署与基础安全

- 根目录 Dockerfile、Compose 配置和精简白名单构建上下文；容器以非 root 用户运行。
- 生产环境要求设置独立演示账号密码；首页、静态资源和论文 API 需登录，健康检查 `/health` 可匿名访问。
- 生产模式默认关闭 `/docs`、`/redoc` 和 `/openapi.json`。
- 设置请求体、单 PDF 上传大小、上传频率、并发上传和总存储额度限制，并阻止带 Origin 的跨站写请求。
- 目前为单实例、单进程的演示保护，不是多用户账号或数据隔离系统。所有访客共享同一个演示论文库。

### 官方材料样例

- `1706.03762v7.pdf` 与 `1706.03762v1.pdf`：识别为同一 arXiv 论文的不同版本；v1 被识别为旧版本。
- `1706.03762v7.pdf`：提取到论文题名、8 位作者、摘要、25 个章节和 58 个带来源的文本块。

- `UnderstandingDeepLearning_02_09_26_C.pdf`：541 页完成基础分页解析；当前没有后台任务队列、处理进度或断点恢复。

官方资料只用于本地测试，没有加入 GitHub 仓库。

## 五、当前明确尚未实现的内容

- 向量检索、混合检索和重排。
- 基于检索结果生成带论文名、版本、页码及原文片段的证据问答。
- 证据充分性检查、拒答和防止无依据引用的回答流程。
- 根据用户意图调用工具的 Agent 编排。
- 论文跨版本差异报告、多篇论文结构化比较和证据跳转。
- OCR 识别、复杂版面/公式/表格解析，以及超长任务的进度和恢复。
- 多用户账号、用户数据隔离和持久化存储。

## 六、重要使用边界

- 这是一个**共享演示账号**，拿到凭证的人共享同一个论文库；不要上传个人毕设、未发表论文、隐私或没有分发权限的资料。
- 演示用户名当前为 `viewer`；密码只保存在 Render 的环境变量中，不能写入本文件、README、提交记录、截图或公开视频。
- 本地已有论文不会自动同步到云端。免费实例没有持久盘，云端资料不能视为可靠备份。
- 免费服务休眠后可能要等待启动；展示前提前访问并确认状态。
- 保持免费方案时不要升级套餐，也不要添加收费的持久磁盘。

## 八、阶段结论与下一阶段建议

第一阶段完成了“能部署、能登录、能导入论文、能查看基础解析结果”的工程闭环，为后续科研助手能力提供了可演示底座。下一阶段应优先把检索、证据引用、回答核验和 Agent 调用连成闭环，而不是先扩张许多独立功能。

建议下一阶段主验收链路为：

```text
上传论文 → 检索相关段落 → 生成带页码和原文依据的回答
→ 检查证据是否支持结论 → 点击引用回到论文原文
```

这样能把“可信科研助手”的核心价值从资料管理推进到真正可验证的科研辅助。
