我们已经做出了以论文上传、基础解析、版本关联、证据检索、单篇问答和跨论文比较为核心的可运行系统。第四轮开发可以按这个范围收尾；比赛要求的六大模块还没有全部覆盖，不能据此宣布整项比赛作品完成。

## 4. 按官方六模块查缺补漏

### 模块一：文件管理与细粒度解析——部分具备

已有：PDF 上传、精确重复识别、同 arXiv 版本关联、分页文本、基础元数据/章节/块。

缺口：正文语义去重、用户覆盖/保留选择、完整 CRUD、批量任务、实际 OCR、长文档可恢复处理、机构/图表/公式/参考文献/附录的可靠结构化。

验收应拆开记录：

- v7 后上传 v1：重命名文件仍能关联；再用无可识别 ID 的近重复文档检查内容相似判定。不能只证明读取到了 arXiv ID。
- 明确展示“已有较新版”，允许用户保留旧版、取消或确认替换；默认建议不得悄悄删除文件。版本差异报告中的结论需可回查。
- 扫描版 1706.03762v1_img.pdf：必须实际取得文字、切块、检索并回到正确页。全文扫描件还应检查漏页和失败状态。
- 541 页教材：检查任务进度、深页检索、内存峰值和中断恢复；同步接口能返回 541 页不代表这些工程要求通过。

### 模块二：抗幻觉问答与多文推理——当前最成熟，仍为部分覆盖

已有：中英混合术语桥接、单篇 RAG、2–5 篇平衡取证、引用映射/来源覆盖、缺证据时停止生成。

需要增加官方细粒度题：第六位作者与机构、Adam 的两个 beta、Base 训练 GPU 数量/型号、big 模型 BLEU 与旧 SOTA 差值、LayerNorm 引用作者/年份；以及 BERT/Transformer、GPT-1/2/3 参数、LN 位置和上下文窗口演化。

每题分别检查“找对证据”和“最终回答正确”。现有检索题集不能替代这些题逐一验证。官方追问示例还涉及省略论文名的上下文问题，当前无完整持久化会话上下文，需单独补齐或明确限制。

### 模块三：阅读与双向翻译——主要缺口

当前是提取文本分页阅读，不是原生 PDF 阅读器。需要原版 PDF 展示、章节导航、原文定位、正文引用与参考文献双向跳转，以及局部翻译、整篇翻译、双语同步。

下一版可以先交付“原版 PDF + 目录/证据定位 + 段落双语对照”，但该最小版仍不等于整篇翻译及全部联动要求通过。代码、公式与参考文献应保留；回答区避免公式源码的偏好不应扩展为删除原 PDF 公式。

### 模块四：搜索、追踪与推荐——只有本地搜索基础

本地库关键词搜索不能代替外部论文搜索下载、参考文献下钻、引用质量筛选、arXiv 更新追踪、相关性推荐、代码可用性和反馈。

最小闭环建议：标题检索 → 核验元数据与公开 PDF 链接 → 用户确认导入 → 基于本地论文给出带依据的推荐理由。外网失败时应有明确状态，不能阻塞已入库论文问答。只显示“相关”标签不算实现推荐算法。

### 模块五：引用图谱与综述——未形成模块

需要真实参考文献解析、库内匹配、带证据的有向引用边、约 20 篇图谱、中心性或 PageRank、带原文来源的综述。必须区分“在当前子图中重要”与“整个领域公认基石”。

最小版可先做真实引用边和中心性、点击节点到论文，再用已有证据生成综述提纲。Future Work 时间线、结合最新文献排除旧 idea 仍是额外缺口；不能仅凭模型判断就宣称一个想法尚无人研究。

### 模块六：写作与数据可视化——未形成模块

需要 idea → Abstract/Introduction/Related Work/真实 References 的提纲、图示脚本、CSV 图表及 Caption、学术中译英。

最小版建议先用库内真实来源生成提纲，使用经过校验的 CSV 列生成折线/柱状图、可下载脚本和图注。统计值应由程序计算，图注引用实际趋势；不能把模型推测当成实验结果。基础图表也不代表题目列出的全部图表类型已覆盖。

## 6. 接下来做什么：建议执行顺序

### A. 第五轮先补官方点名测试：版本策略与扫描件闭环

1. **内容去重与版本交互。** 结合正文相似度和已有标识匹配，解释关联依据；增加保留/取消/确认替换，先防误合并误删除，再做带证据的版本差异。验收是改名后的 v7/v1 与无关论文对照，不只是界面出现弹窗。
2. **上传/解析任务状态与实际 OCR。** 让扫描页进入真实识别、统一切块与索引；展示实际处理页数、失败页和重试状态。先通过整份官方扫描样例，再验证 541 页教材深页检索和任务资源占用。OCR 方案先测本地 CPU 成本，不能默认免费云主机能承担重模型，也不默认当前文本 API 支持图像输入。

这两项直接对应官方点名样例，且复用现有上传、work/version 和证据链，优先级高于继续大改问答卡片。持久队列、全书断点恢复属于额外工程量，需要实测后单列进度，不与初版 OCR 一并报完成。

### B. 让阅读与翻译真正可验收

3. 原生 PDF 阅读、真实章节导航和证据定位，随后接入段落翻译/双语对照。完成后用双栏论文、公式页和扫描页实际操作；继续单列整篇翻译、参考文献双向跳转和同步滚动的剩余范围。

### C. 按验收收益补剩余模块，并增加 Agent 技术深度

4. 真实引用图谱与中心性 → 带来源综述提纲；标题检索/公开论文导入 → 可解释推荐；CSV 校验 → 图表/图注/脚本。按独立小闭环交付，每个模块均有成功、缺数据及失败用例。
5. 将这些能力封装为明确输入输出的工具，接入有限步数的模型工具选择，保留可查看的工具执行摘要、来源与失败状态。是否调用成功由程序校验，不以模型自述“完成”为准。先维持可用的固定工作流，再扩展规划；不为使用某个框架而重写现有系统。

C 的总量仍较大，不能承诺截止前全部做完；每个小闭环结束后按实际用时重新取舍。外部论文持续追踪、完整前沿新颖性判定、多人协作及大规模图谱，排在基本模块和交付材料之后。这里是工期取舍，不表示被延后的官方功能已经满足。
