# TraceScholar 开发路线

## P0：必须形成闭环

1. 保护独立比赛仓库，排除密钥、个人数据、旧数据库和生成文件。
2. 整理官方 PDF 与功能验收表。
3. 建立上传、论文库、阅读器和问答四个核心入口。
4. 建立论文、版本、页码、章节、文本块和证据数据结构。
5. 支持 PDF 分页解析、标题/作者/摘要识别和失败重试。
6. 识别 arXiv ID、DOI、标题和作者，并关联同一论文的多个版本。
7. 支持关键词、向量和重排检索（关键词检索已完成，向量与重排待完成）。
8. 实现带论文名、版本、页码、章节和原文片段的问答（证据检索、跳页和 DeepSeek 证据回答已完成本地真实调用验证）。
9. 实现最小 Agent：意图识别 → 工具选择 → 检索 → 证据检查 → 回答。

### P0 验收主线

`上传 v7 → 上传 v1 → 识别同一论文 → 提问 → 返回页码证据 → 点击跳页 → 比较版本`

## P1：提高项

10. 2–5 篇论文的结构化比较。
11. 扫描 PDF OCR 和超长文档的分批、进度、断点恢复。
12. 本地论文搜索、相似论文推荐和基础引用图谱。
13. 段落翻译、术语解释、摘要和带引用的综述提纲。
14. CSV 上传和基础科研图表。

## P2：进阶优化

15. 双栏、表格、公式、图注和复杂版面解析。
16. 查询改写、多轮检索、逐事实核验和幻觉引用拦截。
17. Agent 日志、重试、超时、缓存、降级和权限控制。
18. 跨版本差异报告、研究演进图谱和反馈评测。
19. AI 率检测、Lean 形式化检查作为可插拔扩展，不占用主流程时间。

## 比赛交付

20. 使用官方测试 PDF 建立可重复的问题集和回归记录。
21. 完成公网演示、测试账号、README、技术文档和演示视频。

## 七天倒排

- 第 1 天：仓库、骨架、数据结构和上传任务。
- 第 2 天：PDF 解析、分页文本和版本识别。
- 第 3 天：检索、证据问答和证据跳页。
- 第 4 天：多论文比较和最小 Agent。
- 第 5 天：OCR、长文档、图谱或写作中择优补齐。
- 第 6 天：官方 PDF 回归、修复和部署。
- 第 7 天：README、技术文档、视频和最终彩排。

## 当前检查点（2026-11-13）

- 第 1 天主体完成：仓库、中文界面、上传、安全检查、逐页文本、论文/版本/章节/文本块/证据数据契约。
- 第 2 天部分完成：题名、作者、摘要、arXiv ID 和版本关系已可用；跨版本差异分析未开始。
- 第 3 天基础检索完成：本地关键词检索、论文范围筛选、证据卡片、资料不足提示和原文页码跳转已可用。
- DeepSeek 证据回答已完成接口、模拟测试与本地真实调用验证；向量检索和重排尚未接入。
- 组委会样例已建立可选回归测试，详见 `docs/OFFICIAL_ACCEPTANCE.md`。
